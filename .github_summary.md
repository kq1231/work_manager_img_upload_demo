## 🎓 Key Architectural Decisions

### Why This Approach?

| Decision | Rationale |
|----------|-----------|
| **Hive for storage** | Fast, type-safe, persistent, no SQL overhead |
| **WorkManager for background** | Reliable, survives restarts, cross-platform |
| **File storage (not bytes in DB)** | Better memory efficiency, easier cleanup |
| **Periodic task only** | Simpler than one-off tasks, checks queue automatically |
| **Max 5 retries** | Prevents infinite loops, user can manually retry |
| **Save first, upload second** | Ensures data never lost, best UX |

### Data Flow

```
Capture → Save Locally → Try Immediate Upload
                              ↓
                         Success? → Cleanup
                              ↓
                         Failed? → Queue
                              ↓
                     WorkManager (15 min)
                              ↓
                         Retry Upload
```

## 🔧 Configuration Options

### Change Upload Interval
`lib/services/workmanager_service.dart`:
```dart
frequency: const Duration(minutes: 15),  // Change to 5, 30, etc.
```

### Change Max Retries
`lib/services/upload_service.dart`:
```dart
if (upload.retryCount >= 5) {  // Change to 3, 10, etc.
```

### Simulate Failures
```bash
curl -X POST http://localhost:5000/api/config \
  -H "Content-Type: application/json" \
  -d '{"simulateFailure": true}'
```
