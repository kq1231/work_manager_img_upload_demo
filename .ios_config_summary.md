## 📱 How It Works on iOS

```
1. App launches
   ↓
2. AppDelegate registers periodic task with 15-min frequency
   ↓
3. iOS schedules task (considers user patterns, battery, etc.)
   ↓
4. Task executes in background (max 30 seconds)
   ↓
5. Our callback uploads pending images
   ↓
6. Task completes → iOS schedules next execution
```

**Important:** iOS controls **actual timing**. Your 15-minute frequency is a **minimum** - iOS may delay based on:
- User behavior patterns
- Battery level
- Charging status
- Time of day
- Network availability

## 🔍 Task Identifier Flow

**Critical:** Identifier must match across all files!

```
Info.plist:
  com.example.workManagerImgUploadDemo.uploadPendingImages
           ↓
AppDelegate.swift:
  withIdentifier: "com.example.workManagerImgUploadDemo.uploadPendingImages"
           ↓
Flutter (WorkManager):
  Task name: "uploadPendingImages"
  (Plugin auto-maps to full identifier)
```

**Mismatch = Tasks won't execute!** ⚠️

## ⚠️ iOS Limitations

### 30-Second Execution Limit
BGTaskScheduler tasks must complete in **30 seconds or less**.

**Our solution:**
- Quick Hive read (milliseconds)
- Efficient upload code
- Exit early if no work

### iOS Controls Timing
You request 15 minutes, but iOS may:
- Delay to save battery
- Skip if device is busy
- Run earlier if device is idle and charging
- Learn from user patterns over time

### Requires User Permission
Users must enable:
- Settings → General → Background App Refresh → ON
- Settings → Your App → Background App Refresh → ON

**If disabled:** Background tasks won't run! ❌

## 📊 iOS vs Android

| Feature | iOS | Android |
|---------|-----|---------|
| **Min Frequency** | 15 min | 15 min |
| **Execution Limit** | 30 sec (hard) | None (system kills if needed) |
| **Reliability** | Less predictable | More predictable |
| **User Control** | Background Refresh toggle | Battery optimization |
| **Testing** | Xcode debugger | adb commands |
| **Notifications** | No NotificationDebugHandler | Yes! Shows notifications |

**Key Takeaway:** Android is more predictable, iOS is more battery-optimized.

## 🎓 iOS Best Practices

### 1. Design for Failure
Don't rely on background tasks always running. iOS may:
- Skip tasks to save battery
- Delay tasks for hours
- Stop tasks if disabled by user

**Solution:** Design app to work even if background tasks fail.

### 2. Optimize for 30 Seconds
```dart
void callbackDispatcher() {
  Workmanager().executeTask((task, inputData) async {
    final start = DateTime.now();
    
    await processUploads();
    
    final duration = DateTime.now().difference(start);
    if (duration.inSeconds > 25) {
      print('⚠️  Approaching 30-second limit!');
    }
    
    return true;
  });
}
```

### 3. Log Everything
iOS debugging is harder than Android. Add comprehensive logs:
```swift
NSLog("✅ Periodic task registered")
NSLog("⚠️  Background App Refresh must be enabled")
```

### 4. Test on Real Device
Simulators **don't support background tasks**. Always test on physical device.

### 5. Use App Regularly
iOS learns usage patterns. The more you use the app, the more reliably background tasks run.

## 🐛 Common Issues

### Issue: "Background tasks not running"
**Checklist:**
- [ ] Background App Refresh enabled in Settings?
- [ ] Physical device (not simulator)?
- [ ] Task identifiers match exactly?
- [ ] BGTaskSchedulerPermittedIdentifiers in Info.plist?
- [ ] Not in Low Power Mode?
- [ ] App used recently?

### Issue: "Tasks worked, then stopped"
**Likely causes:**
- User disabled Background App Refresh
- iOS battery optimization kicked in
- App not used recently (iOS forgot pattern)

**Solution:**
- Ask user to check Background App Refresh
- Encourage regular app usage
- Add in-app reminder about Background Refresh
